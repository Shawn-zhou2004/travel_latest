# Canonical Contracts

## Authority Order
1. `docs/contracts/` for shared enums, permissions, and domain events.
2. `docs/API设计.md` for HTTP, SSE, and WebSocket payloads.
3. `docs/数据库设计.md` for persistence constraints and ownership.
4. `docs/前端交互规范.md` for visible behavior.

## Naming

New endpoints use `/api/v1/itineraries`; `/trips` is not implemented. The canonical aggregate and resource names are `itineraries`, `itinerary_days`, `itinerary_events`, `itinerary_versions`, `generation_jobs`, `import_jobs`, `export_tasks`, `travel_search_jobs`, `travel_offers`, `travel_orders`, and `payment_records`.

Paths use plural kebab-case nouns. JSON fields, event fields, database columns, and frontend API types use snake_case. Public IDs are UUID strings; timestamps are UTC RFC 3339; local itinerary dates use `YYYY-MM-DD`; money is a decimal string plus a three-character ISO currency.

## Shared State

- Itinerary: `draft`, `ready`, `archived`.
- Generation job: `queued`, `understanding`, `searching_poi`, `routing`, `planning`, `validating`, `succeeded`, `failed`, `cancelled`.
- Import job: `queued`, `parsing`, `awaiting_confirmation`, `matching_poi`, `succeeded`, `failed`, `expired`, `cancelled`.
- Export task: `queued`, `running`, `succeeded`, `failed`, `expired`, `cancelled`.
- Community post: `draft`, `pending_review`, `published`, `hidden`, `rejected`.
- Travel order: `PENDING_CONFIRMATION`, `PAYING`, `PAID_PENDING_FULFILLMENT`, `CONFIRMED`, `FAILED`, `REFUNDING`, `REFUNDED`, `CLOSED`.
- Payment record: `pending`, `paying`, `paid`, `failed`, `refunding`, `refunded`.
- Supply confirmation: `pending_confirmation`, `confirming`, `confirmed`, `failed`, `not_supported`.

Every travel-order response includes the independent triplet `status`, `payment_status`, and `fulfillment_status`; no consumer may derive one from another.

## Technical Dependency Map

This is the verbatim shared technical dependency map. Every reconciled product, API, database, technical, and frontend contract explicitly references this section; it controls integration order, not scope.

1. Platform runtime, configuration, authentication, database access, migrations, shared API client, and both application shells.
2. AI itinerary generation with verified AMap POIs and map rendering.
3. Itinerary editing, recalculation, optimization, versions, imports, collaboration, and export.
4. Community publication, itinerary copy, companion requests, chat, notifications, and public search.
5. Supplier search, offers, travel orders, Alipay sandbox payment, refunds, and fulfillment state updates.
6. Checklist, budget, image recognition, guide sessions, narration, TTS, and playback.
7. Provider verification, attractions, experiences, sessions, bookings, commission ledger, membership, entitlements, and itinerary packages.
8. Admin workflows for users, content, providers, orders, tasks, queues, search, and configuration.
9. Real-service acceptance, fault injection, authorization regression, and cross-module correction.

## Change Control

All product capabilities are in scope. Technical dependency order controls integration, not inclusion. A contract change updates API, persistence, event, permission, frontend-state, and test contracts together. Historical terminology is superseded by this directory and must not be used for new work.
