# Permission Matrix

This matrix is enforced by backend authorization. Frontend visibility follows it but never replaces server-side checks. A user who owns a resource retains owner capabilities; an accepted itinerary collaborator has only the role granted by its collaboration record.

| Capability | Anonymous | User | Collaborator | Provider staff | Platform admin |
|---|---|---|---|---|---|
| Read published posts, published public itineraries, attractions, experiences | Read | Read | Read | Read | Read |
| Read link-visible itinerary with a valid token | Read only | Read only | Read only | Read only | Read for support/audit |
| Create, save, copy, import, export, generate, or edit own itinerary | Denied | Owner only | Denied unless editor role | Denied | Audit only unless acting as owner is explicitly delegated |
| Read or edit shared itinerary | Denied except valid link read | Owner; accepted viewer reads; accepted editor writes | Viewer reads; editor writes with version and operation headers | Denied | Audit only; no direct content mutation |
| Publish posts, react, comment, report, create companion request, chat | Denied | Own content and member conversations | Same as user | Own user identity only | Read/audit; moderation actions through state machines |
| Create travel search, travel order, payment, refund request | Denied | Own resources | Denied unless also owner | Denied | Read/audit; cannot fabricate payment or fulfillment |
| Manage provider profile, attractions, experiences, sessions, bookings, provider orders | Denied | Denied | Denied | Only assigned `provider_id` scope | All provider scopes for review and operations |
| Manage users, content, reports, task operations, queue replay, search indexing, configuration | Denied | Denied | Denied | Denied | Allowed through audited admin APIs |
| Read private media, chats, exact addresses, payment callback payloads | Denied | Own authorized resources | Only resources explicitly shared | Assigned provider resources only | Minimum necessary audit access with redaction |

## Role Rules

- Anonymous access is limited to published content and valid link-visible itinerary read models. It cannot copy, save, edit, import, collaborate, chat, or order.
- User access requires a C-end audience token. B-end tokens cannot be used as C-end tokens.
- Collaborator access requires an accepted invitation. `viewer` is read-only; `editor` writes use `If-Match-Version` and `X-Operation-ID`.
- Provider staff access requires a B-end audience token, an assigned provider membership, and a matching `provider_id` on every scoped resource.
- Platform-admin access requires a B-end audience token and `platform_admin`. Mutations use the owning state machine, create an audit record, and publish an Outbox event where a downstream effect exists.
