# 受控多智能体与分域 RAG 设计

更新时间：2026-08-07

## 目标与范围

本设计将当前单一行程生成工作流演进为受控多智能体编排，并将共享旅行资料拆分为按可信度、隐私与用途隔离的 RAG 域。

一期覆盖：

- 行程生成与调整的受控多智能体编排。
- 官方旅行知识、社区经验、用户私有记忆三个 RAG 域。
- 知识入库审核与生成审核两层审核。
- 高德 POI 验证、候选搜索、路线估算和按需时效信息查询。
- 不可变 preview 版本、审计、降级和重试。

一期不覆盖 Neo4j、DeepAgents、自由 Agent 委派或直接业务写入。

二期按需引入 Neo4j 图谱检索 Agent；三期仅在用户明确请求多方案比较、偏好权衡或长程多轮规划时引入 DeepAgents。

一期还覆盖：

- 管理端 WebSearch MCP 候选资料发现、自动检查、人工审核和分域入库。
- 火车与航班 MCP 实时查询、短时 Offer、支付后二次校验和明确标记的模拟出票。

一期不覆盖真实铁路或航班锁座、真实出票、退改签、保存完整乘客证件号、前端直连 MCP，或普通用户直接联网网页搜索。

## 架构原则

LangGraph 是唯一的 Agent 编排和状态机。RabbitMQ Worker 是异步任务消费者，消费 MySQL Outbox 投递的事件并运行 LangGraph；FastAPI 继续负责同步 API、认证、授权和业务事实写入。

规划 Agent 是唯一的任务总控。专业 Agent 不相互委派，不进行自由文本对话，不直接读写业务数据库；它们接收结构化任务并返回结构化结果。所有 Agent 调用、结果摘要、降级和修订记录进入 PostgreSQL checkpoint 与审计存储。

AI 只能创建 preview。用户确认指定 preview 后，现有 ItineraryService 通过版本校验和幂等操作写入 MySQL 行程。AI Agent 永远没有行程、订单、支付、权限或审核状态的直接写权限。

## Agent 契约

| Agent | 输入 | 输出 | 可访问能力 | 禁止事项 |
| --- | --- | --- | --- | --- |
| 规划 Agent | 用户目标、城市、日期、预算、修改指令、证据包、记忆、地图结果、审核问题 | 一个结构化行程草案或澄清请求 | 受控调用以下专业 Agent | 直接访问 RAG、地图或业务数据库；写正式行程 |
| 检索 Agent | 查询、城市、任务类型、允许域 | 证据包、citation、来源等级、分数、冲突与未覆盖项 | 官方与社区 RAG | 读取用户记忆；写知识库 |
| 记忆检索 Agent | user_id、当前任务 | 当前用户的显式 profile/episodic 记忆 | 仅当前用户私有记忆 RAG | 跨用户读取；自动写记忆 |
| 地图 Agent | 城市、POI ID、关键词、候选草案 | 已验证 POI、候选地点、路线估算、时效查询结果 | 高德地图服务 | RAG 检索；完整行程生成；业务写入 |
| 生成审核 Agent | 草案、证据包、地图结果、约束与降级标记 | pass、revise、clarification_required 或 no_result | 只读审计材料与规则 | 修改知识库或业务数据 |
| 知识入库审核 Agent | 待入库资料、来源、候选知识域 | approved、rejected 或 needs_human_review | 内容治理规则和资料内容 | 索引资料；读取私有记忆 |
| Web Search Agent | 城市、搜索词、目标知识域 | 带 URL、来源域名和抓取时间的网页候选资料 | 管理端触发的魔塔 WebSearch MCP | 直接进入 RAG；向普通用户返回网页资料；创建业务记录 |
| 交通查询 Agent | 火车/航班类型、出发地、目的地、日期、人数，或已选 Offer | 短时有效的标准化 Offer 或复核结果 | 魔塔 Train/Flight MCP | 创建订单、支付、出票、读取 RAG 或完整乘客证件信息 |

审核 Agent 的 revise 响应必须为机器可用的结构化问题列表。例如：

```json
{
  "decision": "revise",
  "issues": [
    {
      "code": "over_budget",
      "severity": "error",
      "activity_ids": ["day-2-activity-1"],
      "instruction": "Replace this activity with a cited lower-cost candidate."
    }
  ]
}
```

可修订问题最多自动修订两次。硬失败，包括官方知识不可用、POI 不存在或跨城市、私有记忆越权与不可消解的证据冲突，立即返回澄清、无结果或不可用状态，不进入修订循环。

## 行程生成与调整

Worker 消费 ai.generation_requested 后执行以下 LangGraph 流程：

```text
validate_request
  -> 并行执行 memory_retrieval_agent 和 retrieval_agent
  -> planning_agent 生成初稿
  -> map_agent 验证候选 POI、城市与粗路线
  -> generation_review_agent
  -> revise 时由 planning_agent 修订，最多两轮
  -> map_agent 最终 POI 与路线复核
  -> generation_review_agent 最终审核
  -> save_immutable_preview_with_audit
  -> user_confirmation
```

规划 Agent 只综合结构化的检索、记忆、地图和审核结果，不直接调用外部服务。高优先级事实依次为高德实时验证、人工审核的官方规则和供应商事实、已审核 POI 与城市模板、已审核社区经验、用户显式记忆；模型自身推断不能作为旅行事实。高优先级与低优先级证据冲突时使用高优先级结果；高优先级证据缺失、过期或互相冲突时返回澄清。

每次修改当前方案均创建新 generation job 和新 preview 版本。旧 preview、引用、工具结果、审核结论和修订记录保持不可变。用户只能确认指定 preview；确认后仍使用既有版本校验和幂等写入机制。

一期一次只生成一个可确认 preview。多方案比较与偏好权衡留给三期 DeepAgents。

用户明确要求交通安排时，规划 Agent 可以调用交通查询 Agent 返回候选车次或航班，并把它们作为 preview 建议。候选 Offer 不创建订单；用户必须在交通搜索页重新查询最新 Offer，再主动选择和购买。

## 分域 RAG

三个 RAG 域共用 Embedding 服务、索引 Worker、重试、删除语义和 citation 格式，但必须使用独立 Milvus collection 和 Elasticsearch index。

| 域 | Milvus collection / Elasticsearch index | 内容 | 允许读取者 | 证据作用 |
| --- | --- | --- | --- | --- |
| 官方旅行知识 | travel_official_knowledge_v1 | 高德验证 POI、旅行规则、城市模板 | 检索 Agent、审核与地图相关的只读调用 | 高可信旅行事实 |
| 社区经验 | travel_community_knowledge_v1 | 已发布且审核通过的公开攻略、体验和建议 | 检索 Agent | 中可信经验与灵感，不单独支撑高风险事实 |
| 用户私有记忆 | user_memory_v1 | 用户明确保存的 profile、episodic memory | 记忆检索 Agent，必须精确过滤 user_id | 个性化约束，不是旅行事实 |

每个知识切片保留 document_id、chunk_id、source_type、source_id、city_code、poi_id、language、visibility、status、source_updated_at 和 content_hash，并新增：

```text
knowledge_domain
authority_level
reviewed_at
next_review_at
source_version
supersedes_document_id
```

私有记忆额外保存 memory_id、user_id、memory_type、consent_source 与 deleted_at。所有私有记忆查询都在向量召回和结果合并阶段执行 user_id 强制过滤。

实时交通 Offer、价格、余量、席别和航班状态绝不写入 RAG。它们是订单域中的短时查询快照，不是长期旅行知识或事实型问答依据。

检索 Agent 先选择允许的域，再在每个域内并行执行 dense 与 BM25 检索、域内 RRF 去重和置信度判断，最后按证据等级合并。各场景的检索策略如下：

| 场景 | 必查域 | 可选域 | 禁止域 |
| --- | --- | --- | --- |
| 行程生成与调整 | 官方旅行知识、用户私有记忆 | 社区经验 | 其他用户记忆 |
| 事实型问答 | 官方旅行知识 | 社区经验，且明确标为经验 | 用户记忆，除非问题涉及个人偏好 |
| 攻略与灵感问答 | 官方旅行知识 | 社区经验 | 其他用户记忆 |
| 社区审核与后台运营 | 当前待审资料或对应知识域 | 无 | 所有用户私有记忆 |

## 知识治理

官方资料、社区发布内容与用户显式记忆均先经过知识入库审核 Agent。

```text
资料提交
  -> 知识入库审核 Agent
  -> approved：指定 RAG 域，保存事实资料并写 Outbox
  -> Worker：切片、向量化、写对应 Milvus 与 Elasticsearch
  -> indexed
  -> rejected：保留理由，不进入检索库
  -> needs_human_review：管理员可通过、拒绝或编辑后重新审核
```

社区资料必须已发布且经自动审核通过或人工审核通过，才能进入社区经验 RAG。编辑社区帖子时，旧版本立即停止召回，新版本重新审核并在通过后索引；隐藏或删除时，Worker 异步删除该资料在 Milvus 与 Elasticsearch 的所有切片，删除成功后才完成下架。

官方 POI 默认复核周期为 90 天，旅行规则为 180 天。超过周期的资料标为 needs_review，不得作为唯一高风险事实依据；重新审核后更新版本、审核时间和下一次复核时间。城市模板不强制到期，但每次编辑或再审核都创建新版本。

用户私有记忆仅由用户在界面中明确新增、编辑或确认时写入。普通对话、模型推断、浏览记录、preview 和确认行程均不得自动写入长期记忆。用户删除记忆时，PostgreSQL 原始记录和所有私有检索投影一起删除；投影删除失败必须可重试，且删除标记后的记忆不可再检索。

### WebSearch MCP 候选资料

一期只有平台管理员可从知识运营后台输入城市、搜索词和目标知识域，触发 Web Search Agent 调用魔塔 WebSearch MCP。

```text
管理员发起搜索
  -> Web Search Agent
  -> 魔塔 WebSearch MCP
  -> 网页候选资料
  -> 知识入库审核 Agent
  -> needs_human_review
  -> 管理员通过、编辑或拒绝
  -> 通过后才写 MySQL 原始知识源并进入官方或社区 RAG
```

候选资料只保存标题、摘要、URL、域名、发布日期、抓取时间、查询词、目标城市和抓取摘要哈希。候选网页默认不是旅行事实，不能直接回答普通用户，也不能直接写入向量索引。政府、景区、地图服务和受授权供应商官方站点可被审核为较高来源；普通媒体和旅游攻略只能作为社区经验级补充。普通用户的一期问答和行程生成不调用 WebSearch MCP。

## 实时交通 MCP 与模拟交易

交通能力由可替换的 `TrainOfferProvider`、`FlightOfferProvider` 和 `TransportOfferProvider.revalidate` 后端契约提供。魔塔 MCP 是生产查询实现；具体服务地址、工具名和认证方式不预设在代码中，也不暴露给前端。未配置或调用失败时返回 `REALTIME_TRANSPORT_UNAVAILABLE`，不创建 Offer、订单或支付记录。

```dotenv
MAGIC_MCP_TRAIN_URL=
MAGIC_MCP_TRAIN_TOOL=
MAGIC_MCP_FLIGHT_URL=
MAGIC_MCP_FLIGHT_TOOL=
MAGIC_MCP_WEBSEARCH_URL=
MAGIC_MCP_WEBSEARCH_TOOL=
MAGIC_MCP_API_KEY=
MAGIC_MCP_TIMEOUT_SECONDS=15
```

交通查询 Agent 有两个只读入口：消费者在火车票或机票搜索页主动查询；规划 Agent 在用户明确要求交通安排时查询候选建议。后端调用 MCP、标准化并保存短期不可变 Offer；前端只读取后端 Offer，绝不直连 MCP。

每个 Offer 至少包含来源、外部 Offer ID、交通类型、出发地、目的地、出发到达时间、时长、车次或航班号、席别或舱位、余量、金额和币种、有效期、查询时间、退改规则和供应商快照。行程 preview 中的“查看可购票方案”会带入出发地、目的地和日期到交通搜索页，并重新查询；不得复用 preview 中的旧报价。

```text
用户选择 Offer
  -> 选择席别/舱位与靠窗、靠过道或无偏好
  -> 输入一次性演示乘客资料
  -> 创建订单
  -> 支付宝沙箱支付
  -> 服务端验签确认支付
  -> payment_record.paid Outbox
  -> Worker 重新通过 MCP 复核同一 Offer
  -> MockTrainSupplierAdapter 或 MockFlightSupplierAdapter
  -> 模拟出票成功，或出票失败待退款
```

创建订单前必须校验 Offer 未过期且可用。支付确认后，Worker 必须复核同一车次或航班、已选席别或舱位、价格和余量；一致时才允许 Mock Adapter 分配模拟车厢/座位或航班座位并确认订单。无票、价格变化、席别不可用或 Mock Adapter 拒绝时，订单进入出票失败待退款，用户可发起全额模拟退款。MCP 临时不可用属于可重试故障，Worker 不得宣称出票成功。

一期座位选择是偏好而非真实锁座。前端必须展示“座位偏好，最终以出票结果为准”；Mock Adapter 可以返回明确标记的模拟票号和座位，例如 `05车 12A` 或 `18A`。完整乘客证件号仅在创建订单请求的内存生命周期中使用，不得保存到 MySQL、PostgreSQL、RAG、日志、Outbox、Agent 审计或浏览器本地持久化。订单和模拟票券仅保存脱敏姓名与脱敏证件号。

## 地图 Agent

地图 Agent 一期支持：

- 按 POI ID 验证地点存在、城市归属、坐标、地址和标准名称。
- 在指定城市按关键词搜索候选 POI。
- 估算相邻活动的距离、时长和交通方式。
- 按需查询营业时间等时效信息，并携带获取时间。

地图无法可靠返回营业时间、票价或交通状态时，规划 Agent 不得将其输出为确定事实。初稿阶段可做候选验证和粗路线估算；最终审核前必须复核最终 POI。路线估算不可用时允许生成 preview，但必须标记路线待复核，不得声称确定交通时长。

## 失败治理与降级

| 依赖或 Agent | 处理方式 |
| --- | --- |
| 官方旅行知识 RAG | 停止任务并由 Worker 重试；重试耗尽后 unavailable |
| 地图 Agent 的最终 POI 验证 | 停止任务；不能生成包含未验证地点的 preview |
| 生成审核 Agent | 停止任务；不得跳过质量门禁 |
| 社区经验 RAG | 继续，只使用官方资料，记录社区补充不可用 |
| 用户记忆检索 Agent | 继续，不应用记忆，记录本次未使用个人偏好 |
| 路线估算 | 继续，标记路线待复核 |
| WebSearch MCP | 仅阻止管理员本次补库任务；不影响既有 RAG 与消费者请求 |
| Train / Flight MCP 首次查询 | 返回实时票务查询不可用；不创建 Offer、订单或支付记录 |
| Train / Flight MCP 支付后复核 | Worker 重试；重试期间不生成票券、不确认订单 |
| Neo4j 或 DeepAgents | 回退到一期主链 |

依赖不可用属于可重试故障。没有可信证据、证据冲突无法消解、POI 不存在或跨城市、私有记忆越权属于确定性业务失败，直接进入 clarification_required 或 no_result。

## 审计与展示

消费者端仅显示阶段化进度：理解需求、检索可靠资料、结合个人偏好、验证地点与路线、检查预算和安排、生成可确认方案。最终 preview 可显示引用、地点验证、预算结论与待确认项。

消费者端不得显示模型推理、内部 prompt、Agent 对话、完整证据包或其他用户数据。

管理员后台保存 Agent 和配置版本、输入输出摘要、耗时、重试、降级标记、citation、证据等级、冲突、地图工具结果、审核问题码、知识审核决定、人工复核操作、资料版本以及索引和删除状态。管理员视图只展示去标识化审计摘要，不展示用户提示、私有记忆正文或会话正文。

管理员还可查看 WebSearch 查询词、目标城市、候选 URL/域名、抓取时间、摘要哈希和审核决定。交通审计保存 MCP Provider、工具名称、请求参数摘要、耗时、错误码、Offer 数量、查询时间、有效期、二次校验与模拟出票结果；不得保存 MCP 密钥、完整乘客证件号、原始网页正文或模型推理。

消费者端新增火车票和机票 Tab：出发地、目的地、日期、人数、结果列表、席别/舱位、座位偏好、一次性乘客资料、支付与出票状态。展示状态包括支付处理中、模拟出票中、已出票和出票失败待退款。前端必须明确区分模拟出票与真实出票。

一期的 Agent 权限与 RAG 路由固定在代码和版本化配置中。管理员管理资料、审核与复核，但不配置任务可调用的 Agent 或 RAG 域。

## 验收标准

- Agent 无法访问未获准的 RAG 域，尤其不得跨用户读取私有记忆。
- 三个域的索引、检索、删除和重建相互隔离。
- 官方或地图高可信证据可覆盖社区冲突；不可消解冲突返回澄清。
- 审核 revise 最多两轮；硬失败不进入修订循环。
- POI 存在性和城市验证是生成 preview 的必经门禁。
- 可选依赖降级标记可持久化和查询；关键依赖失败触发 Worker 重试。
- 修改生成新的不可变 preview，旧版本保留；只确认指定版本后才写 MySQL 行程。
- 管理员仅见审计摘要，消费者仅见阶段和可解释的最终结果。
- WebSearch 候选资料未经自动审核与人工确认，不能进入任一 RAG 域。
- 火车与航班 MCP 查询仅由后端生成短期不可变 Offer；前端不直连 MCP。
- MCP 查询超时、未配置或无效响应时，不创建 Offer、订单或支付记录。
- Offer 过期、余量不足或不属于当前用户的 Offer 不能创建订单。
- 支付后复核只接受相同车次或航班、席别或舱位、价格与余量；失败时不得伪造票券。
- 完整证件号不进入数据库、日志、Outbox、Agent 审计、RAG 或客户端本地持久化。

## MCP 增补

WebSearch MCP 与实时 Train/Flight MCP 的完整职责、治理、交易边界和验收标准见 [MCP 知识治理与实时交通交易设计](./2026-08-07-MCP知识治理与实时交通交易设计.md)。该增补是本设计的一部分：网页搜索候选必须经过知识治理才可进入分域 RAG；实时票务 MCP 只产生短期订单 Offer，不进入 RAG，支付后由 Worker 调用模拟履约 Adapter 出票。
