# 田野笔记设计

**状态：** 已完成需求与视觉方向确认，待用户审阅后编写实施计划。

## 目标

将当前的泛旅行帖子社区升级为“田野笔记”：每篇已发布内容都是一份可参考、可复制的旅行作品，由冻结的行程快照、公开旅行复盘和照片组成。读者可阅读、点赞、收藏、评论和举报，并能一键复制行程到自己的工作台继续编辑。

田野笔记服务于两类明确任务：

1. 作者完成或规划一次旅行后，从行程工作台发布可供他人参考的行程和复盘。
2. 读者从社区发现适合自己的旅行方案，复制为独立草稿，而不是手工重建路线。

## 非目标

- 不创建与现有 `Post`、`Comment`、`PostReaction`、`PostFavorite`、`PostMedia` 并行的第二套社区实体或互动系统。
- 不把作者的私人备注、预算、清单、未公开媒体或原始行程的未来改动自动公开。
- 首版不支持视频、协同编辑他人的公开行程、将公开行程合并到现有行程、或按复盘段落设置不同可见范围。
- 首版不把普通文本帖子作为田野笔记主入口；社区发布必须关联行程快照。

## 当前差异

当前 `/community` 是已发布 `Post` 的文本信息流。前端编辑器仅收集标题、城市和正文；详情使用弹窗；`content_type` 虽已有 `itinerary` 枚举，但没有行程版本绑定、冻结快照、发布入口、公开路线展示或复制到工作台能力。

现有基础可复用：

- `Itinerary`、`ItineraryDay`、`ItineraryEvent` 与 `ItineraryVersion.snapshot` 提供版本化行程事实。
- `Post` 提供发布、审核、隐藏、搜索索引和社区知识审核链路。
- `PostMedia`、`Comment`、`PostReaction`、`PostFavorite`、`ContentReport` 提供图片与互动事实。
- 行程工作台已能编辑独立行程，并通过既有版本化操作创建新版本。

## 产品流程

### 作者发布

1. 作者在自己拥有编辑权限的行程工作台点击“发布田野笔记”。
2. 页面默认选择当前行程版本，也允许选择该行程已有的历史版本。
3. 发布页只读展示将公开的按天行程快照；作者填写标题、公开复盘、封面和排序图片。
4. 作者预览后提交，系统创建 `pending_review` 的 `Post`。
5. 管理员审核通过后笔记变为 `published` 并进入田野笔记首页；拒绝或隐藏沿用现有审核原因和审计记录。

### 读者参考与复制

1. 读者在 `/community` 浏览已发布田野笔记，按目的地、关键词、最新或推荐发现内容。
2. 读者进入独立详情页，阅读作者复盘、照片和按天路线。
3. 点击“复制到工作台”后，后端只读取已发布笔记的冻结快照。
4. 后端为读者创建新的 `Itinerary`、`ItineraryDay`、`ItineraryEvent` 与初始 `ItineraryVersion`，并保存公开笔记来源关系。
5. 前端立即跳转到 `/itineraries/{new_itinerary_id}`。读者可自由改动副本，原笔记和原作者行程均不会改变。

### 社区互动

田野笔记复用现有的点赞、取消点赞、收藏、取消收藏、评论、举报和管理员隐藏能力。互动目标始终是 `Post`，不复制或转移到行程实体。

## 数据设计

### Post 扩展

保留 `Post` 作为公开内容的单一实体；田野笔记固定使用 `content_type = "itinerary"`。新增字段应至少包括：

| 字段 | 类型 | 规则 | 用途 |
| --- | --- | --- | --- |
| `itinerary_id` | UUID nullable FK | 发布时必填；原行程删除后置空，不影响笔记快照 | 原始行程审计与权限追踪 |
| `itinerary_version_id` | UUID nullable FK | 发布时必填；原版本删除后置空，不影响笔记快照 | 指向发布时选择的版本 |
| `itinerary_snapshot_json` | JSON nullable | 发布时从版本快照深拷贝；发布后不可改 | 公开、可复制的行程事实 |
| `recap_text` | Text nullable | 田野笔记必填，最长 20,000 字符 | 作者公开复盘 |
| `cover_media_id` | UUID/string nullable | 必须属于该帖已完成图片媒体 | 信息流和详情页首图 |
| `copy_count` | Integer | 默认 0，非负 | 成功复制后的展示与排序统计 |

迁移应为新增字段和约束，不能修改已应用的历史 migration。字段可先允许为空，以保护历史 `note` 内容；服务层必须保证新建或提交 `itinerary` 内容时四个必需事实存在：`itinerary_id`、`itinerary_version_id`、`itinerary_snapshot_json`、`recap_text`。

### 快照边界

发布快照使用 `ItineraryVersion.snapshot`，并只包含公开行程所需的字段：行程标题、开始/结束日期、按显示顺序排列的天、日期、地点 ID、地点快照、开始/结束时间、地点说明和行程事件备注。它不包含作者身份认证信息、协作者、预算、清单、私密媒体、操作历史、共享 token 或支付数据。

快照一经提交即不随原行程更新。作者更新自己的行程后，如需重新公开，必须再次选定版本并提交新的田野笔记；首版不就已发布笔记提供原地编辑快照的能力。

### 图片

继续使用 `PostMedia` 保存多图顺序；`cover_media_id` 必须引用当前帖关联图片之一。图片的上传和完成校验复用现有私有媒体对象存储链路，并在发布前验证媒体归属、用途、状态和 MIME 类型。首版只接受图片，不支持视频。

### 副本来源

在 `Itinerary` 新增可空 `source_post_id` FK，引用复制来源 `Post`，删除来源帖子时置空。它是副本来源的唯一事实记录，必须满足：

- 能显示“复制自：{田野笔记标题}”。
- 同一复制行为可幂等处理，避免网络重试创建重复行程。
- 复制后的行程只归复制者所有，不为原作者增加协作者关系。
- 统计在成功创建副本后递增，失败和重试不重复计数。

## API 契约

现有 `/posts` 资源继续承载田野笔记。新增或调整 API 以明确的请求和响应 schema 表达，禁止让前端构造或信任行程 JSON。

| 接口 | 权限 | 行为 |
| --- | --- | --- |
| `POST /itineraries/{itinerary_id}/field-notes` | 行程 owner/editor | 从指定版本创建审核中田野笔记，服务端生成冻结快照。请求包含标题、复盘、版本 ID、封面媒体 ID、媒体 ID 列表。 |
| `GET /posts?content_type=itinerary` | 公开 | 分页返回已发布田野笔记信息流，支持目的地和关键词筛选。 |
| `GET /posts/{post_id}` | 公开 | 返回田野笔记详情，包括复盘、照片、路线摘要、按天快照和互动计数。 |
| `POST /posts/{post_id}:copy-itinerary` | 已登录消费者 | 从已发布快照创建独立行程副本，使用 `Idempotency-Key`，返回新行程摘要和来源笔记。 |
| `GET /posts/me/field-notes` | 已登录消费者 | 返回当前作者的审核中、已发布、被拒绝和已隐藏田野笔记。 |
| 现有互动接口 | 已登录消费者 | 保持对 `Post` 的点赞、收藏、评论、举报与撤销动作。 |

发布和复制服务必须分别验证：发布者拥有行程编辑权限；版本属于该行程；图片属于发布者且已完成；被复制笔记是 `published`；快照结构完整；复制请求具有幂等键。不得用客户端上传的 `snapshot_json` 作为公开或创建副本的事实源。

## 页面设计

### 田野笔记首页

路径保持 `/community`，用户可见名称改为“田野笔记”。页面是编辑化旅行内容档案流，而不是普通文本列表或密集瀑布流。

- 顶部为目的地发现、关键词搜索、推荐/最新排序和目的地筛选。
- 首篇精选内容使用大幅真实旅行照片，显示路线天数、地点数量、复盘引言和明确的复制入口。
- 后续使用有节奏的不等比例编辑网格；每张卡必须在不打开详情时展示封面、标题、目的地、天数、地点数量、复盘摘要、作者和互动摘要。
- 复制动作与点赞、收藏区分；前者是主任务，后者是次级工具。
- 空、加载、搜索无结果、无可复制行程和网络失败状态必须各自给出明确下一步。

### 田野笔记详情

替换当前的帖子详情弹窗，使用 `/community/{post_id}` 独立路由。

- 首屏使用真实封面图片、标题、作者、目的地和路线摘要，标题不放进浮动卡片。
- 复盘文字和照片交替呈现，保证长内容可读性。
- 行程以垂直路线轨迹和按天章节展示，严格保留快照内的地点顺序。
- 桌面端右侧固定摘要和“复制到工作台”主操作；移动端固定底部工具栏。
- 点赞、收藏、评论、举报保持可用但不抢占复制任务。

### 发布页

从行程工作台打开，路径为 `/itineraries/{itinerary_id}/publish-field-note`。

- 先显示只读行程快照与版本信息。
- 再填写标题、公开复盘、封面和照片排序。
- 提交前展示明确说明：发布的路线内容会冻结；私人预算、清单和未选图片不会公开；后续编辑原行程不改变笔记。
- 发布成功后跳转“我的田野笔记”或对应的审核中详情状态。

### 工作台来源状态

从公开笔记创建的行程在工作台显示简洁来源标记和原笔记链接。它不能阻止编辑，也不应覆盖或混入原始行程信息。

## 视觉规范

田野笔记作为消费者端后续重构的视觉样板。实现时使用 `redesign-existing-projects` 处理现有产品的改造，并用 `frontend-design` 约束多状态、表单、时间线和响应式交互。

视觉语言为“精致旅行编辑部 + 可操作路线档案”，延续 Field / Travel，而不是复制普通社交瀑布流。

- 深海墨蓝 `#102B3A`：导航、高对比结构、详情首图遮罩。
- 雾白 `#F3F7F5`：阅读和编辑背景。
- 海玻璃青 `#167A76`：路线信息、选中和保存状态。
- 琥珀黄 `#D99824`：日期、Day 编号、地点序号、焦点状态。
- 珊瑚红 `#CE644E`：发布和复制到工作台的主要行动。
- 标题使用具有编辑感的中文 sans；正文使用可长读的中文 system sans；日期、Day、路线元数据使用等宽字体。
- 不使用渐变球、紫蓝渐变、米色杂志模板、无意义装饰、过度圆角卡片或页面级浮动卡片。
- 动效只服务图片加载、路线展开和复制成功跳转；必须支持 `prefers-reduced-motion`。

## 审核、搜索与知识边界

田野笔记继续经过现有帖子审核和举报处理。只有 `published` 内容可出现在公开流、详情、复制接口和搜索结果中；被拒绝、隐藏或审核中的内容对非作者不可读、不可复制。

已发布田野笔记可沿用现有社区知识审核流程，作为“社区经验”候选来源；它不能单独证明价格、营业时间、路线实时状态、库存或票务等高风险事实。田野笔记快照和复盘不自动进入官方知识域。

## 错误处理

| 场景 | 后端结果 | 前端反馈 |
| --- | --- | --- |
| 行程不存在或无编辑权限 | `404` 或 `403` | 说明无法从该行程发布并返回工作台。 |
| 指定版本不属于行程 | `422` | 提示重新选择可用版本。 |
| 行程快照为空或结构无效 | `422` | 提示先完善行程后再发布。 |
| 图片未完成或不属于作者 | `422` 或 `403` | 标记对应图片，保留其余草稿输入。 |
| 笔记未发布、已隐藏或不存在 | `404` | 详情和复制均显示不可用状态。 |
| 复制过程失败 | `409`、`422` 或 `503` | 不跳转；提供重试且不重复创建行程。 |
| 幂等重试 | 返回首次创建结果 | 跳转同一个新行程，不重复增加复制数。 |

## 测试与验收

### 后端

- 发布仅允许 owner 或已接受 editor，且只能冻结其所属行程版本。
- 服务端生成的快照与选定版本一致，客户端伪造快照不会生效。
- 原行程更新后，已发布笔记详情仍返回原快照。
- 非发布者不能读取审核中笔记、复制未发布笔记或为他人行程发布。
- 复制会完整保留日、事件、显示顺序和地点快照，创建归属复制者的新行程；原行程不变。
- 同一幂等键重试不创建第二条行程、不重复增加 `copy_count`。
- 发布、审核、隐藏、图片权限、点赞、收藏、评论、举报和搜索过滤的既有回归测试持续通过。
- 新增模型字段附带 Alembic revision，并按仓库流程验证升级、降级一版、再次升级。

### 前端

- 首页能显示田野笔记行程摘要、封面、复盘摘要、筛选和空/错误状态。
- 详情页在桌面和移动端均能阅读复盘、查看按天路线、互动和复制。
- 复制成功跳转到新工作台，来源标记可见；失败时没有误跳转或重复草稿。
- 工作台可打开发布页，能选择版本、上传并排序照片、预览和提交审核。
- 页面符合现有 Vue、TypeScript、路由守卫和认证请求模式；运行 `npm run typecheck` 与 `npm run build`。

### 浏览器验收

1. 创建一个多日行程并在工作台提交田野笔记，包含复盘和图片。
2. 管理员审核发布。
3. 未登录访客可阅读首页和详情；非作者不能看到审核中内容。
4. 消费者登录后点赞、收藏、评论，并执行一次复制。
5. 确认跳转的新工作台可编辑，且原笔记与原行程未变化。
6. 检查窄屏布局中的照片、路线文字、固定复制栏、评论和焦点状态无裁切或重叠。

## 实施顺序

1. 定义迁移、模型、快照服务和来源记录。
2. 完成发布、详情、列表、作者列表和幂等复制 API 及后端测试。
3. 完成行程工作台发布入口和发布表单。
4. 将社区首页升级为田野笔记信息流，并实现独立详情页与互动。
5. 完成复制跳转、来源标记、审核后台适配和媒体选择。
6. 执行类型检查、构建、后端测试、迁移验证和浏览器验收。
