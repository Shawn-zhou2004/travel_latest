# 显式 AI 记忆与旅行档案同步设计

## 目标

让用户可以在 AI 助手页创建、编辑、删除自己的显式记忆；并允许用户主动把个人设置中的旅行偏好同步为一条可管理的 AI 长期记忆。

本设计不从聊天内容自动推断或写入记忆，不修改公共 RAG，也不让 AI 自行决定创建记忆。

## 用户体验

### 助手页的“我的记忆”

- 保留空状态文案：`尚无保存的旅行偏好。`
- 标题区域增加“新增记忆”按钮。
- 点击后打开表单，用户填写：
  - 记忆类型：`个人偏好`（`profile`）或 `旅行片段`（`episodic`）。
  - 记忆名称：例如“饮食偏好”。
  - 记忆内容：普通文本输入。前端保存为 `{"text": "用户输入内容"}`，不要求用户手写 JSON。
- 创建成功后，新的记忆立即出现在列表中。
- 每条已有记忆保留编辑与删除操作；编辑使用与创建一致的表单，不再要求用户输入 JSON。
- 删除保持现有软删除行为，前端从列表移除。

### 个人设置页的“同步为 AI 记忆”

- 在旅行偏好设置区增加明确按钮：`同步为 AI 记忆`。
- 该按钮不在保存设置时自动触发；用户必须主动点击。
- 同步成功后显示明确状态：当前设置已更新到 AI 旅行档案。
- 同步目标固定为当前用户唯一的一条：
  - `memory_type="profile"`
  - `memory_key="travel_profile"`
  - `source="user_settings"`
  - `confidence=1.0`
- `memory_value` 结构：

```json
{
  "departure_city": "可为空",
  "interest_tags": ["吃吃喝喝", "citywalk"],
  "travel_pace": "relaxed",
  "traveler_type": "family"
}
```

- 再次点击同步时更新同一条 `travel_profile`，不会创建重复记忆。
- 用户可在助手页查看、编辑或删除该条旅行档案；若随后再次从设置页同步，会重新创建或覆盖该条档案，以当前设置为准。

## 后端设计

### 已有显式记忆 CRUD

保留已有端点：

- `GET /api/v1/ai/memories`
- `POST /api/v1/ai/memories`
- `PATCH /api/v1/ai/memories/{memory_id}`
- `DELETE /api/v1/ai/memories/{memory_id}`

创建请求继续要求 `memory_type`、`memory_key`、`memory_value`、`source`、`confidence`。前端将普通文本转换为对象后再提交。

### 设置同步端点

增加一个用户专属端点：

```text
POST /api/v1/users/me/settings:sync-ai-memory
```

端点不接受客户端传入的偏好内容，而是读取当前登录用户的 MySQL `UserSettings`，构造固定 `travel_profile` 值，再写入 PostgreSQL AI 记忆库。这避免客户端伪造“来自设置”的内容。

实现逻辑：

1. 按当前 `user_id` 读取或创建 `UserSettings` 默认记录。
2. 组装 `travel_profile` 的固定 JSON 值。
3. 在 PostgreSQL `ai_memories` 中按 `(user_id, memory_key="travel_profile")` 查询未删除记录。
4. 存在时更新内容、来源、置信度并递增 `projection_version`。
5. 不存在时创建 profile 记忆。
6. 更新或创建都写入 `ai_memory_projection_tasks`，由现有投影 Worker 更新 USER_MEMORY 私有 RAG。
7. 返回最新的记忆响应。

同步操作的所有权仅由当前认证用户决定；不允许指定任意 user ID 或 memory ID。

## 数据边界与私有 RAG

```text
用户主动创建记忆 / 主动同步设置
  -> PostgreSQL ai_memories
  -> ai_memory_projection_tasks
  -> MemoryProjectionWorker
  -> USER_MEMORY 域 Milvus + Elasticsearch
  -> 生成工作流的 PrivateMemoryProfileLoader
```

- 只有显式 AI 记忆会进入 USER_MEMORY 私有 RAG。
- 单纯点击“保存个人设置”不会同步；只有点击“同步为 AI 记忆”才会创建/更新 `travel_profile`。
- 记忆更新或删除时，投影 Worker 先删除旧向量/关键词块，再写入新版本，防止检索到过期内容。
- 私有记忆读取仍需 user ID、删除状态和 `projection_version` 二次校验，防止投影滞后泄露或复活旧数据。
- 普通聊天、模型回答、preview 确认和网页临时资料仍不自动进入长期记忆。

## 前端接口与状态

- 在 `frontend-c/src/features/ai/assistantApi.ts` 增加 `createAiMemory` 与 `syncSettingsToAiMemory`。
- 在 `AiAssistantPage.vue` 中以 `ref` 管理记忆表单打开状态、编辑目标、类型、名称、文本内容和提交状态。
- 创建/更新完成后，局部更新 `memories` 列表，不需要重载全部对话。
- 在 `SettingsPage.vue` 中增加单独的同步状态和错误提示；同步按钮不能与“保存设置”隐式耦合。

## 错误处理

- 创建、更新、删除、同步失败均显示 API 返回的具体错误消息。
- 同步期间禁用同步按钮，避免重复提交。
- 空记忆名称或内容在前端禁止提交；后端仍保留字段和 JSON 对象校验。
- 私有 RAG 投影是异步过程：创建/同步 API 成功只表示 PostgreSQL 事实和投影任务已写入；若投影延迟，生成工作流通过现有版本闸门安全降级，不使用过期数据。

## 测试

- 后端：设置同步首次创建、重复同步更新同一条记录、用户隔离、投影任务创建、删除后再次同步可重新创建。
- 后端：同步内容严格来自 MySQL `UserSettings`，不接受客户端伪造的设置值。
- 前端助手页：空状态显示、新增记忆、编辑记忆、删除记忆和 API 失败状态。
- 前端设置页：同步请求、成功提示、失败提示和提交中禁用。
- 保留并运行既有私有记忆投影与 owner/version 闸门测试。

## 不在本次范围

- 不自动从聊天中提取记忆。
- 不将个人设置每次保存自动写入 AI 记忆。
- 不将用户私有记忆写入公共 OFFICIAL 或 COMMUNITY RAG。
- 不修改 LangGraph 行程生成图的节点数量或权限边界。
