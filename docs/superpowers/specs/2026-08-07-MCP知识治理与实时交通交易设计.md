# MCP 知识治理与实时交通交易设计

更新时间：2026-08-07

本设计是《受控多智能体与分域 RAG 设计》的 MCP 增补。它定义 WebSearch MCP 的知识治理职责，以及魔塔 Train/Flight MCP 的实时交通查询、订单、支付宝沙箱支付和模拟出票边界。

## 范围

一期覆盖：

- 管理端 WebSearch MCP 候选资料发现和人工审核入库。
- 火车与航班 MCP 实时查询、短期 Offer 快照和交通查询 Agent。
- 类同程旅行的火车票/机票搜索、席别/舱位、座位偏好、一次性乘客资料、订单、支付与模拟出票体验。
- 支付后 MCP 二次校验与模拟出票失败待退款。

一期不覆盖真实铁路或航班锁座、真实出票、退改签、保存完整乘客证件号、前端直连 MCP，或普通用户直接联网网页搜索。

## MCP 边界

MCP 是受控 Agent 的外部工具层，不是 RAG，也不能绕过订单、支付和 Worker 履约边界。

```text
WebSearch MCP
  -> Web Search Agent
  -> 网页候选资料
  -> 知识入库审核 Agent + 管理员人工复核
  -> 官方旅行知识 RAG / 社区经验 RAG

Train / Flight MCP
  -> 交通查询 Agent
  -> 短期实时 Offer 快照
  -> 前端展示与用户选择
  -> 订单、支付、Worker 履约
  -> Mock Supplier Adapter 模拟出票
```

Web Search Agent 和交通查询 Agent 不创建订单、不支付、不出票、不直接写 RAG。规划 Agent 可在用户明确要求交通安排时调用交通查询 Agent，但只能把候选 Offer 放入 preview 建议；用户必须在交通搜索页重新查询并主动选择后，订单服务才可创建订单。

## WebSearch MCP

一期只允许平台管理员从知识运营后台发起 WebSearch MCP。输入为城市、搜索词和目标知识域。

```text
管理员发起搜索
  -> Web Search Agent 调用魔塔 WebSearch MCP
  -> 保存候选资料
  -> 知识入库审核 Agent
  -> needs_human_review
  -> 管理员通过、编辑或拒绝
  -> 通过后才写 MySQL 原始知识源并进入目标 RAG 域
```

候选资料只保存标题、摘要、URL、域名、发布日期、抓取时间、查询词、目标城市和抓取摘要哈希。候选网页默认不是旅行事实，不能直接回答普通用户，也不能直接写入 Milvus 或 Elasticsearch。

政府、景区、地图服务和受授权供应商官方站点可被审核为较高来源；普通媒体和旅游攻略只能作为社区经验级补充。普通用户的一期问答和行程生成不调用 WebSearch MCP。

## 实时交通查询

后端定义可替换的 Provider 契约：

```text
WebSearchProvider.search(request) -> WebSearchCandidateResult
TrainOfferProvider.search(request) -> TransportOfferResult
FlightOfferProvider.search(request) -> TransportOfferResult
TransportOfferProvider.revalidate(selected_offer) -> OfferValidation
```

魔塔 MCP 是上述 Provider 的生产查询实现。具体 MCP 地址、工具名与认证方式不得硬编码或暴露给前端：

```dotenv
MAGIC_MCP_TRAIN_URL=
MAGIC_MCP_TRAIN_TOOL=
MAGIC_MCP_FLIGHT_URL=
MAGIC_MCP_FLIGHT_TOOL=
MAGIC_MCP_WEBSEARCH_URL=
MAGIC_MCP_WEBSEARCH_TOOL=
MAGIC_MCP_API_KEY=
MAGIC_MCP_TIMEOUT_SECONDS=15
```

交通查询 Agent 可由消费者主动的火车票/机票搜索页调用，也可由规划 Agent 在明确交通需求下调用。后端调用 MCP、标准化并保存短期不可变 Offer；前端只读取后端 Offer，绝不直连 MCP。

Offer 必须保存以下信息：

```text
source
external_offer_id
transport_type: train / flight
origin / destination
train_number 或 flight_number
seat_or_cabin_class
availability
amount / currency
valid_until
retrieved_at
change_rules
provider_snapshot
```

实时 Offer、价格、余量、席别和航班状态不进入 RAG。它们属于订单域的短时查询快照，不能作为长期旅行知识或事实型回答依据。

MCP 未配置、超时、认证失败或返回无效响应时，后端返回 `REALTIME_TRANSPORT_UNAVAILABLE`，不创建 Offer、订单或支付记录；前端显示“实时票务查询暂不可用”，仅提供重试。

## 交通购买演示

消费者端提供火车票与机票 Tab：出发地、目的地、日期、人数、结果列表、席别/舱位、靠窗/靠过道/无偏好、一次性乘客信息，以及支付和出票状态。

```text
用户选择 Offer
  -> 选择席别/舱位与座位偏好
  -> 输入一次性演示乘客资料
  -> 创建订单
  -> 支付宝沙箱支付
  -> 服务端验签确认支付
  -> payment_record.paid Outbox
  -> Worker 重新通过 MCP 复核 Offer
  -> MockTrainSupplierAdapter / MockFlightSupplierAdapter
  -> 模拟出票成功，或出票失败待退款
```

创建订单前必须校验 Offer 尚未过期且余量可用。支付确认后，Worker 必须复核相同的车次或航班、席别或舱位、价格和余量：

| 复核结果 | 处理 |
| --- | --- |
| 价格一致且仍有余量 | Mock Adapter 分配模拟车厢/座位或航班座位，订单确认 |
| 无票、价格变化、席别不可用 | 进入出票失败待退款，用户可发起全额模拟退款 |
| MCP 临时不可用 | Worker 重试；不生成票券，不确认订单 |
| Mock Adapter 出票失败 | 进入出票失败待退款 |

一期座位选择仅表示偏好，前端必须提示“座位偏好，最终以出票结果为准”。Mock Adapter 可返回明确标记的模拟票号和座位，例如 `05车 12A` 或 `18A`，但不得声称已由 12306 或航司锁定。

完整乘客证件号仅在创建订单请求的内存生命周期中使用，禁止写入 MySQL、PostgreSQL、RAG、日志、Outbox、Agent 审计或浏览器本地持久化。订单和模拟票券仅保存脱敏姓名与脱敏证件号。真实接入时应新增独立的加密乘客档案、受管密钥、用户授权、实名校验和保留期限。

规划 preview 中的交通建议提供“查看可购票方案”入口，带入出发地、目的地和日期后重新查询实时 Offer；不得复用 preview 中的旧报价。

## 审计与验收

管理端审计保存 WebSearch 查询词、城市、目标域、候选 URL/域名、抓取时间、摘要哈希和审核结论。交通审计保存 MCP provider、工具名、请求参数摘要、耗时、错误码、Offer 数量、查询时间、有效期、二次校验与模拟出票结果。

审计不得保存 MCP 密钥、完整乘客证件号、完整原始网页正文、完整私有记忆或模型推理。

验收要求：

- WebSearch 候选资料未经自动审核与人工确认不得进入任一 RAG 域。
- 火车与航班 MCP 查询均仅由后端生成短期不可变 Offer；前端不直连 MCP。
- MCP 查询失败不生成 Offer、订单或支付记录。
- 过期、无余量或非当前用户的 Offer 不能创建订单。
- 支付后复核失败不生成票券，订单进入出票失败待退款。
- Mock 出票结果明确标记为模拟，并包含模拟票号和座位分配。
- 完整证件号不进入数据库、日志、Outbox、Agent 审计、RAG 或客户端本地持久化。
- 未来只替换 Mock 履约 Adapter 为受授权供应商 Adapter；现有后端 Offer、订单、支付和 Worker 边界不变。
