# AI 行程 Agent 新版设计（历史决策记录）

> 状态：本设计记录已被原 V1 PRD 的 V1.2 行程模块改造方案取代；其中的交互决策仍作为参考。

## 1. 文档定位

本文档是现有 `ai-travel-platform-prd.md` 的新版核心能力设计，不替换原项目的长期方向。它将原 PRD 中的基础 Agent、地图和行程能力收敛为当前版本的 P0 验收范围，并把社区、找搭子、聊天、当地服务商、预约支付、数字导游和外部平台链接解析保留为后续版本路线图。

当前版本的产品目标是：让用户输入目的地、出行日期和偏好标签，或导入平台分享链接/图片，获得一份基于真实 POI、可编辑、可分享、可协作的多日行程。

## 2. 产品边界

### 2.1 当前版本 P0

- 首页提供 AI 规划入口，跳转到行程创建页。
- 输入目的地、出行日期和偏好标签，AI 生成多日行程。
- 所有行程事件必须绑定地图检索到的真实 POI。
- 以日期列、事件卡片和地图组成行程工作台。
- 支持添加、删除、复制、替换、拖拽排序事件，以及新增日期。
- 支持地图 POI 搜索和按区域/类别浏览城市资源池。
- 用户编辑后自动重算当天路线、距离和通勤时间。
- 每天提供主动触发的“一键优化路线”。
- 支持平台内部分享链接导入和图片识别导入。
- 支持图片识别结果确认、修正和 POI 校验。
- 支持云端保存、私密、链接可见和邀请共同编辑。
- 支持结构化实时协作、分享链接和 Word 导出。

### 2.2 后续版本

- 小红书等外部平台链接直解析。是否接入取决于官方 API/合作权限。
- 社区内容、公开攻略流和关注关系。
- 找搭子、私聊和群聊。
- 当地服务商、预约、支付及 B 端管理。
- 数字导游、语音讲解和更复杂的实时位置能力。

## 4. 核心用户流程

### 4.1 创建与生成

1. 用户从首页进入 AI 规划。
2. 选择目的地、出行日期和偏好标签。
3. Agent 解析约束，调用地图服务检索真实 POI。
4. Agent 按日期和区域聚合 POI，生成初始顺序。
5. 地图服务计算路线、距离和通勤时间。
6. 系统校验地点存在、路线可计算、日期不越界。
7. 生成可编辑的行程工作台。

### 4.2 工作台编辑

工作台采用“左侧按天编排、右侧地图联动”的布局。

- 日期列代表每一天，支持新增 Day。
- 事件卡片展示图片、名称、类型、区域、建议停留时间以及到下一站的通勤信息。
- 用户可以复制、删除、替换、添加和拖拽排序事件。
- 添加事件打开 POI 搜索面板；搜索结果展示名称、类型和行政区。
- 地图资源池支持按区域和游玩、吃喝、购物、住宿等类别筛选。
- 地图支持单日路线和全部天数总览，按日期使用不同颜色。

普通编辑遵循用户顺序。增删、复制、替换或拖拽完成后，系统在短暂防抖后重算当前日期的路线、距离和通勤时间，不擅自重排地点。

每个日期列提供“一键优化路线”。该操作由用户主动授权 Agent 按距离、通勤时间、区域聚合和营业时间重新排序当前日期的 POI。执行前显示预计节省的距离/时间，执行后提供撤销；优化只影响当前日期。

### 4.3 导入

#### 平台分享链接

- 校验分享链接的访问权限。
- 读取日期、地点、排序和路线信息。
- 导入后创建用户自己的行程副本，不修改原行程。
- 只读链接只能复制导入，不能继承原行程编辑权限。

#### 图片识别

1. OCR/VL 识别地点名称、日期和顺序。
2. 展示识别结果和置信度。
3. 用户确认或修正地点。
4. 将地点匹配到真实地图 POI。
5. 无法匹配的地点要求重新搜索，不生成虚构 POI。
6. 用户确认后创建可编辑行程并计算路线。

小红书链接直解析不属于本版范围。用户可以在后续版本中通过官方开放平台能力接入；未获得官方权限时不使用非官方爬虫。

## 5. 账号、分享与协作

用户必须登录后创建、保存和编辑行程。行程可见性包括：

- **仅自己可见**：只有拥有者可查看和编辑。
- **链接可见**：持链接者可查看，不可编辑。
- **邀请共同编辑**：只有被邀请者可以编辑。

共同编辑采用结构化实时同步，不引入 CRDT 富文本协作。每个行程、日期、事件和操作具有唯一 ID；添加、删除、复制、排序、新增日期和权限修改通过 WebSocket 广播给同一行程房间的协作者。后端使用版本号防止旧数据覆盖新数据。路线重算结果同步给所有协作者。断线时客户端暂存未提交操作，重连后重新提交并执行版本校验。

首版不做评论、消息、操作历史和多人光标显示。

## 6. 技术边界与服务职责

- **前端工作台**：渲染日期列、事件卡片、地图、搜索、拖拽、权限和协作状态。
- **行程服务**：管理行程、日期、事件、排序、权限、版本号和操作记录。
- **Agent 服务**：解析用户需求、图片结果和导入内容；只输出可校验的 POI 候选与行程结构。
- **地图服务**：POI 检索、地理编码、营业时间、路线和距离时间计算。
- **协作服务**：维护行程房间、广播结构化操作和处理版本冲突。
- **异步 Worker**：处理 AI 生成、图片识别、路线重算和 Word 导出。

所有耗时任务通过任务状态和进度反馈给前端。模型不能直接写入未经 POI 校验的地点。

## 7. 错误处理

- POI 无法匹配：提示用户重新搜索。
- 路线计算失败：保留用户顺序与旧路线，提示重试。
- AI 生成失败：允许重新生成，不保存半成品行程。
- 图片置信度低：标记待确认，不直接入行程。
- 协作版本冲突：拒绝旧版本覆盖，提示同步最新状态。
- WebSocket 断开：保留本地未提交操作，恢复连接后重新提交。
- Word 导出失败：保留行程数据，允许重新导出。

## 8. 首版验收标准

1. 用户能根据目的地、日期和标签生成多日真实 POI 行程。
2. 每个事件支持添加、删除、复制、替换和拖拽排序。
3. 用户可以新增日期并在指定日期添加 POI。
4. 支持单日路线、全程总览和当前日期一键优化路线。
5. 普通编辑后自动重算距离与通勤时间，且不改变用户顺序。
6. 支持平台分享链接和图片识别导入，图片结果需用户确认。
7. 支持私密、链接可见和邀请共同编辑。
8. 至少两名协作者能实时看到结构化编辑变化。
9. 支持复制查看链接和导出 Word。
10. 关键失败不会丢失已保存行程或覆盖用户的有效编辑。

## 9. 与原 PRD 的整合规则

原 PRD 中的技术栈、部署、数据可靠性、地图 POI 校验、事件驱动和后续平台能力继续保留，但必须按本设计重新标注优先级。当前版本的验收只覆盖本文 P0；原 PRD 的社区、服务商、支付等内容作为后续独立模块，不得成为本版本行程 Agent 的阻塞依赖。
