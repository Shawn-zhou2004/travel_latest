# Day 1 基础工程与数据层设计

## 目标

建立 AI 智能旅行平台的可运行开发基线：FastAPI 模块化单体、Vue 3 C/B 端路由壳、MySQL/Redis/RabbitMQ/Elasticsearch/Nginx 本地基础设施，以及可重复执行的 Alembic 初始迁移。

## 范围

Day 1 只覆盖基础工程和行程核心数据模型，不实现 AI、地图、社区、支付或实时协作业务。

### 基础设施

- Docker Compose 编排 MySQL 8、Redis 7、RabbitMQ 3、Elasticsearch 8 和 Nginx。
- 所有凭据通过 `.env` 注入；仓库只提交 `.env.example`。
- 服务使用固定开发端口和健康检查，便于本地启动验证。

### 后端

- FastAPI 模块化单体，提供 `/api/v1/health` 健康检查。
- SQLAlchemy 2 async engine + asyncmy 访问 MySQL。
- Alembic 管理迁移；模型使用 UUID 字符串主键、UTC 时间戳。
- 配置集中在 `app/core/config.py`，异常响应预留统一结构。

### 核心数据模型

首个迁移包含：

- `users`：账号和状态。
- `user_sessions`：Refresh Token 哈希、设备、过期和撤销状态。
- `itineraries`：拥有者、目的地、日期范围、可见性、版本和状态。
- `itinerary_days`：行程日期、显示顺序和标题。
- `itinerary_events`：绑定真实 POI 的地点事件和用户排序。
- `route_segments`：相邻事件间的路线、距离、通勤时间和计算状态。

关键约束：手机号唯一；会话 token 只存哈希；行程日期范围为 1 至 7 天；同一行程日期唯一；事件顺序在日期内唯一；POI ID 在同一日期内唯一；路线段属于同一日期；删除行程级联删除子资源；行程可见性只允许 `private`、`link`、`collaborative`。

### 前端

- `frontend-c` 和 `frontend-b` 均使用 Vue 3 + Vite + TypeScript。
- Day 1 只提供可启动的路由壳和占位页面，不实现业务组件。

## 验证

1. `docker compose config` 成功解析。
2. Compose 服务健康检查可通过。
3. Alembic upgrade/downgrade/upgrade 可重复执行。
4. FastAPI 健康接口返回 200 和服务状态。
5. C/B 端开发服务器能启动并显示各自首页。
6. 数据库表、外键、唯一约束和索引与本文档一致。

## 非目标

- 不引入微服务、Kubernetes 或生产级密钥管理。
- 不在前端暴露高德、模型、支付或数据库凭据。
- 不提前创建社区、订单、支付和供给方表；这些随对应 Day 的业务设计加入。
