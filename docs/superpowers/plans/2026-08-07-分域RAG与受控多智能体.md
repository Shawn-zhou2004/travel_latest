# 分域 RAG 与受控多智能体 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the shared public RAG read path with isolated official, community, and user-memory domains, then run itinerary generation through bounded typed agents in one LangGraph workflow.

**Architecture:** Keep MySQL generation jobs, Outbox, RabbitMQ, PostgreSQL checkpoints, immutable previews, and itinerary confirmation unchanged. Add a domain catalog that owns three fixed Milvus/Elasticsearch store pairs and enforces domain/user scope before dense or BM25 retrieval. Refactor workflow helpers into typed retrieval, memory, planning, map, and review agents; no agent receives database write authority or free delegation capability.

**Tech Stack:** FastAPI, SQLAlchemy/Alembic/MySQL, PostgreSQL asyncpg checkpoints, LangGraph, SiliconFlow BGE-M3, Zilliz Milvus, Elasticsearch, RabbitMQ, Vue 3.

## Global Constraints

- Keep `EMBEDDING_MODEL=BAAI/bge-m3`, `EMBEDDING_DIMENSIONS=1024`, cloud Milvus, and local Elasticsearch unchanged for this migration.
- Use fixed domain stores: `travel_official_knowledge_v1`, `travel_community_knowledge_v1`, and `user_memory_v1`; never accept collection/index names from API input.
- AI agents create previews only; `ItineraryService` remains the only writer of confirmed MySQL itineraries.
- Official RAG and final map validation are mandatory; community, private memory, and route estimation are degradable with persisted flags.
- Private-memory retrieval filters `user_id` in dense search, BM25 search, and post-merge validation.
- Generation review permits at most two structured revisions; deterministic evidence/POI/privacy failures do not enter a revision loop.
- Do not add Neo4j, DeepAgents, browser MCP access, free agent delegation, or live transport/websearch calls in this plan.
