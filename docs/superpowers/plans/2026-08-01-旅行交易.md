# Travel Commerce Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver authorized travel supply search, immutable offers, platform pre-orders, Alipay sandbox payment, callback verification, active query, refunds, and consumer/admin order views without fabricating fulfillment.

**Architecture:** Orders owns search jobs, offer snapshots, travel orders, payments, callback audits, and refunds. Supplier and Alipay access live behind integrations; MySQL state transitions and Outbox events remain authoritative.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, RabbitMQ, Redis locks, Alipay sandbox SDK, Vue 3, Element Plus, pytest, Vitest.

## Global Constraints

- Requires foundation auth, Outbox, configuration, and frozen supplier/payment contracts.
- Offer snapshots are immutable and cannot create orders after `valid_until`.
- Payment success requires server callback signature, merchant order, amount, buyer, and state checks; browser results cannot set paid state.
- Order responses always return `status`, `payment_status`, and `fulfillment_status`.
- Missing supplier capability returns explicit empty/unavailable results, never fake prices, inventory, booking, or confirmation.
