# Integration and Acceptance Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate every domain module into one deployable system, validate all real-service boundaries, seed demonstrable data, and run repeatable contract, integration, fault, permission, and browser acceptance suites.

**Architecture:** This plan owns only integration boundaries: application/router registration, worker routing, migration ordering, Compose wiring, seeds, fixture setup, contract suites, and E2E flows. It does not rewrite domain rules; defects discovered here are returned to their owning module plan and verified through regression tests.

**Tech Stack:** Docker Compose, FastAPI, Alembic, pytest, RabbitMQ, Redis, Elasticsearch, Playwright or agent-browser, Vue/Vite, MySQL, AMap, Qwen, OSS, Alipay sandbox.

## Global Constraints

- Start only after every domain plan has passed its own module gate and marked its contract version compatible.
- Use real configured infrastructure and third-party services for smoke checks; never bypass a failed real integration with synthetic success.
- MySQL retains business fact; integration tests may reset dedicated test databases only, never a user-supplied production database.
- Every cross-module defect receives a regression test in the owning module or integration suite.
- This workspace currently has no Git repository; do not use worktree or commit steps until repository metadata is restored.
