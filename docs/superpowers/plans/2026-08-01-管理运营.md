# Admin Operations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the full platform-admin workspace for users, content, reports, narrations, providers, attractions, experiences, orders, payments, memberships, search, queues, task operations, audit, and system configuration.

**Architecture:** The admin module is a server-authorized orchestration/read-model boundary. It invokes public domain services for state changes and never directly bypasses a resource state machine.

**Tech Stack:** FastAPI, SQLAlchemy, RabbitMQ management client, Elasticsearch, Vue 3, Element Plus, ECharts, pytest, Vitest.

## Global Constraints

- Requires foundation and the read/write contracts from every domain module.
- Every admin endpoint requires `admin` token audience plus `platform_admin`; provider workspace uses separate provider scope guards.
- Admin actions write audit records and appropriate Outbox events.
- Administrators cannot fabricate payment, supplier fulfillment, booking verification, or user-authenticated content edits.
