# Contract and Platform Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Freeze a complete full-scope contract and create the shared FastAPI, Vue, Docker, configuration, authentication, migration, and test foundation required by every travel-platform module.

**Architecture:** The foundation is a modular FastAPI monolith, two independent Vue 3/Vite applications, and a separate worker using MySQL as the source of truth. Domain modules depend on shared contracts and core services; no domain module starts until its API schema, table ownership, events, permissions, and failure behavior are documented and tested.

**Tech Stack:** Python 3.11+, FastAPI, Pydantic v2, SQLAlchemy 2.x, Alembic, pytest, MySQL 8, Redis 7, RabbitMQ 3, Elasticsearch 8, Vue 3, Vite, TypeScript, Pinia, Vue Router, Axios, Element Plus, Docker Compose, Nginx.

## Global Constraints

- Implement every feature in `docs/AI旅行平台需求文档.md`; technical order controls integration only and does not remove functionality.
- Use `/api/v1`, plural kebab-case API paths, snake_case JSON fields, UUID public IDs, UTC RFC 3339 timestamps, and decimal strings for money.
- Use `itineraries`, `itinerary_days`, `itinerary_events`, `itinerary_versions`, `generation_jobs`, `import_jobs`, `export_tasks`, `travel_search_jobs`, `travel_offers`, `travel_orders`, and `payment_records` as canonical names.
- MySQL is the sole business fact source. Redis is cache/session/rate-limit/presence state; RabbitMQ transports events; Elasticsearch indexes search; OSS stores media.
- All create-task, import, export, order, payment, and refund APIs require `Idempotency-Key`. Itinerary writes require `If-Match-Version`; collaborative writes also require `X-Operation-ID`.
- Do not ship secrets. Root `.env` is ignored; `.env.example` contains names, formats, non-secret examples, and enablement switches only.
- External-service failures return explicit safe errors or empty results. Never fabricate AMap, supplier, payment, OCR, model, or fulfillment success.
- Use red-green-refactor development: write and run a failing test before the smallest implementation that passes it.
- This workspace has no Git metadata. Do not create a commit until the user initializes or restores the repository.
