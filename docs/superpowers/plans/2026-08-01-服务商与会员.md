# Provider and Membership Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver provider onboarding, attraction management, experiences and sessions, reservations and verification, promotion tracking, commission ledger, membership entitlements, and purchasable itinerary packages.

**Architecture:** Providers owns provider-scoped business records and requires both role and `provider_id` scope checks. Membership and packages reuse the shared order/payment infrastructure rather than creating another payment callback path.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, RabbitMQ, Redis locks, Vue 3, Element Plus, pytest, Vitest.

## Global Constraints

- Requires foundation, itinerary, commerce, media, and frozen provider/membership contracts.
- Provider APIs validate role and `provider_id` server-side; hidden menus are not authorization.
- Attractions bind verified AMap POIs. External ticket links use approved HTTPS domains and record clicks only.
- Session capacity is short-term locked during order creation and released after payment expiry; no overselling.
- Membership, experience, and package purchases reuse payment records/callback handling and Outbox fulfillment.
- The commission ledger records accounting intent only and never performs real split settlement or withdrawal.
