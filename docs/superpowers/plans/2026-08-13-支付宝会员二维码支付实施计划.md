# 支付宝会员二维码支付实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将会员购买支付改为本站展示支付宝沙箱二维码、三秒轮询服务端支付事实并在确认后即时授权会员。

**Architecture:** 会员购买订单保持现有独立模型，新增多个可审计的支付尝试，每个尝试对应一个支付宝预下单支付单号和十分钟二维码有效期。后端复用现有 RSA2 签名和验签能力，新增 `alipay.trade.precreate` 与面向支付尝试的主动查询；前端本地渲染二维码、按页面可见性轮询，所有会员授权继续复用既有幂等授权服务。

**Tech Stack:** FastAPI, SQLAlchemy async, MySQL, Alembic, existing Alipay sandbox RSA2 adapter, Vue 3, TypeScript, local QR renderer, pytest, Vitest.

## Global Constraints

- 使用 `alipay.trade.precreate`，不跳转支付宝收银台网页。
- 二维码有效期固定为 10 分钟。
- 页面可见时每 3 秒查询，隐藏时暂停，重新可见时立即查询。
- 二维码过期或关闭后仅允许用户手动重新生成，不自动创建新支付尝试。
- 重新生成复用会员购买订单，产生新支付尝试和新支付单号；旧尝试不可再次展示。
- 只有支付宝异步验签通知或服务端主动查询能确认支付并授权会员。
- 支付二维码、签名、私钥、公钥、原始回调和完整交易查询响应不得写入公开响应或日志。
- 不修改旅行订单 WAP 支付逻辑；会员二维码支付是独立支付路径。
- 不修改已应用迁移；共享工作区存在并行改动，不回退无关变更，也不创建提交。
