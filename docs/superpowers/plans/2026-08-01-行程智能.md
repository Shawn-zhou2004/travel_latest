# Itinerary Intelligence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the real-POI itinerary workflow: AI generation, editable itinerary workspace, routes, versions, imports, collaboration, and DOCX export.

**Architecture:** The itineraries module owns itinerary aggregates and versioned write operations. `maps`, `ai`, `imports`, and `exports` expose explicit services to the module; all long-running work is represented by persistent jobs and published through Outbox events.

**Tech Stack:** FastAPI, Pydantic v2, SQLAlchemy 2.x, Alembic, Redis, RabbitMQ, AMap Web Service/API JS, DashScope Qwen/Qwen-VL, OSS, python-docx, Vue 3, TypeScript, Pinia, Element Plus.

## Global Constraints

- Requires the completed foundation plan and frozen itinerary, map, AI, import, export, SSE, and WebSocket contracts.
- Use only `/api/v1/itineraries`, never `/trips`; all POI events require verified AMap POI IDs.
- Every structural write requires `If-Match-Version`; collaborative writes also require `X-Operation-ID`.
- Ordinary edits preserve display order. Optimizations and natural-language adjustments require a preview and explicit confirmation.
- Agent output is Pydantic-validated; only deterministic application services persist itinerary state.
- Every task uses red-green-refactor and adds success, permission, conflict/idempotency, and external-failure tests.
