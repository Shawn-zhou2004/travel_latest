# 群聊与实时消息实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将同行计划改为首个成员接受时创建正式群聊，铃铛按群聚合未读消息，并通过可靠 WebSocket 实现在线即时收发。

**Architecture:** 保留现有 `CompanionRequest`、`CompanionApplication` 和 `Conversation` 模型边界。首次接受申请在一个数据库事务内校验群名和群头像、创建/关联群聊并加入两名成员；后续接受只增加成员。消息继续通过 REST 持久化，提交成功后由 Redis Pub/Sub 广播到所有 API 进程的 WebSocket 连接，前端使用一次性实时票据、自动重连和历史补齐。

**Tech Stack:** FastAPI, SQLAlchemy async, MySQL, Redis Pub/Sub, Vue 3 Composition API, TypeScript, Vitest, pytest.

## Global Constraints

- 同行计划发布和管理员审核不创建用户可见群聊。
- 第一个申请人被接受时，群聊名称和群头像均为必填；任一缺失不得改变申请状态。
- 第三个及后续申请仍由发起人审核，接受后加入现有群聊。
- 铃铛只显示有未读消息的群聊和未读数量，不显示“申请已通过”等独立流水通知。
- 消息必须先成功持久化再广播；WebSocket 广播失败不能回滚已提交消息。
- WebSocket 连接使用一次性实时票据和成员校验，不在 URL 中传访问令牌或用户 ID。
- 现有工作区包含大量未提交改动；只修改本计划列出的业务文件，不回退其他改动，不创建提交。
