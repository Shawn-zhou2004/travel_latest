# 显式 AI 记忆与旅行档案同步 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让用户能在 AI 助手页管理显式记忆，并能从个人设置页主动同步一条可投影到私有 RAG 的旅行档案。

**Architecture:** 显式记忆继续以 PostgreSQL `ai_memories` 为事实源，现有投影任务将其异步写入 USER_MEMORY 私有 RAG。新增一个用户设置同步 API，它只从服务端 MySQL `UserSettings` 读取值，按固定键 `travel_profile` 更新或创建 AI profile 记忆；前端将普通文本转换为受控 JSON 对象，不要求用户输入 JSON。

**Tech Stack:** Vue 3、TypeScript、Pinia、Vitest、FastAPI、Pydantic、SQLAlchemy、asyncpg、PostgreSQL、Milvus、Elasticsearch。

## Global Constraints

- 用户设置保存不得自动创建或更新 AI 记忆；只有用户点击同步按钮才触发同步。
- `travel_profile` 固定为当前用户唯一的 `profile` 记忆，重复同步必须更新同一条而非创建重复记录。
- 设置同步 API 不接受客户端提供的设置值，必须在服务端读取当前用户 MySQL `UserSettings`。
- 显式记忆更新和删除必须继续写入 `ai_memory_projection_tasks`，以保持 USER_MEMORY 私有 RAG 一致。
- 普通聊天、模型回答、preview 确认和联网临时资料不得自动写入长期记忆。
- 保留助手页空状态文案：`尚无保存的旅行偏好。`
- 不引入新的前端组件库或状态管理库。

- [ ] **Step 5: 在用户设置路由增加同步端点**

端点读取当前用户 `UserSettings`。若不存在，创建默认 `UserSettings(user_id=claims.user_id)` 并 flush；构造固定值后调用 AI memory service。不要从请求体读取偏好值。

```python
@router.post("/users/me/settings:sync-ai-memory", response_model=MemoryResponse)
async def sync_settings_to_ai_memory(
    claims: CurrentConsumer,
    session: Session,
    memory_service: Annotated[AIMemoryService, Depends(get_ai_memory_service)],
) -> MemoryResponse:
    settings = await session.get(UserSettings, claims.user_id)
    if settings is None:
        settings = UserSettings(user_id=claims.user_id)
        session.add(settings)
        await session.flush()
    memory = await memory_service.sync_travel_profile(claims.user_id, {
        "departure_city": settings.departure_city,
        "interest_tags": list(settings.interest_tags),
        "travel_pace": settings.travel_pace,
        "traveler_type": settings.traveler_type,
    })
    return MemoryResponse.model_validate(memory)
```
