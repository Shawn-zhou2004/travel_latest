# Community Communication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build community publishing, public itinerary copies, reactions, comments, reports, companion matching, real-time chat, unread state, blocks, notifications, and searchable public content.

**Architecture:** Community, chat, and notifications own separate aggregate tables and expose authenticated APIs plus realtime delivery. MySQL persists all facts; RabbitMQ updates Elasticsearch and notification projections through idempotent Outbox consumers.

**Tech Stack:** FastAPI, SQLAlchemy, Alembic, Redis, RabbitMQ, Elasticsearch, Vue 3, Pinia, WebSocket, Vitest, pytest.

## Global Constraints

- Requires foundation auth/realtime tickets and the frozen community, chat, search, media, and public-itinerary-copy contracts.
- Anonymous users read only published posts and open companion listings; all writes require authentication.
- Public itinerary publication fixes a sanitized version; it removes contacts, precise lodging addresses, and chat content.
- Message creation uses `client_message_id` idempotency; MySQL is the source of truth and Redis only tracks presence/unread caches.
- Every task has success, authorization, duplicate/conflict, and unavailable-search or realtime-reconnect tests.
