# 子智能体任务契约

本目录是手动分发子智能体时的当前实现基线。`docs/API设计.md` 是完整目标契约，其中包含尚未实现的能力；子智能体不得仅根据该文件假设现有路由、表或前端类型已经存在。

每次分发必须同时提供：

1. 对应的本目录模块 brief。
2. `docs/contracts/说明.md`、`docs/数据库设计.md`、`docs/API设计.md`。
3. 允许修改和禁止修改的文件范围。
4. `docs/模块集成验收清单.md`。

实施顺序：先读当前 source 和模块 brief，后用目标契约确认最终方向。若二者冲突，停止并在 handoff 中说明，不得静默替换当前协议。

## 当前共享基线

- 所有 HTTP 路由通过 `backend/app/api/router.py` 装配在 `/api/v1` 下。
- 消费端 API client 为 `frontend-c/src/services/api.ts`，管理端 API client 为 `frontend-b/src/services/api.ts`；它们是受保护共享文件。
- 消费端模块接口类型通常放在功能目录中，例如 `frontend-c/src/features/itineraries/api.ts`。
- MySQL 是业务事实源。新模型需要 ORM、Alembic revision、测试和 MySQL 升级/回滚验证。
- 所有跨模块异步副作用使用 MySQL Outbox 与 RabbitMQ Worker，不直接写另一个模块私有表。
- 新增行程结构写必须使用 `If-Match-Version` 与 `X-Operation-ID`，并经过 `ItineraryService`。
- 外部服务失败必须返回明确状态；不得返回虚构成功数据。

## 交付方式

子智能体可以修改自己模块目录内的模型、服务、schemas、router、功能级前端 API 类型、组件和测试。不得直接修改共享 API 装配、Alembic 链或共享 API client。

涉及新持久化模型或新顶级 router 时，采用两阶段方式：

1. 子智能体先完成模块内 ORM、服务、schemas、router、测试和明确的 migration proposal。
2. 最终集成者负责 `backend/app/api/router.py`、`backend/alembic/env.py` 和单一 Alembic revision 链的接入。
3. 集成者解除共享阻塞后，子智能体恢复实现并完成模块验收。

子智能体不能因为缺少迁移就把数据写进内存、前端状态、JSON 临时字段或其他模块私有表。完成后在 `docs/handoffs/` 写模块 handoff，列出实际 API、模型、前端类型、迁移需求、测试结果和风险。
