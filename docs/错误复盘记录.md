# 错误复盘记录

本文用于简要记录项目故障，方便后续定位同类问题。每次故障恢复后追加一条记录，不填写密钥、Token、用户隐私或完整请求正文。

## 记录模板

### YYYY-MM-DD：错误名称

- 现象：用户看到的错误或异常行为。
- 原因：最终确认的根因。
- 修复：采取的代码或环境修复。
- 验证：用于确认修复有效的测试或结果。

## 2026-08-11：智能规划依赖项暂时不可用

- 现象：选择长沙市、日期和三个偏好后，智能规划最终提示“AI 规划依赖项暂时不可用”，浏览器和 API 无明显报错。
- 原因一：Elasticsearch `192.168.142.50:9200` 曾停止运行，导致 AI runtime 初始化失败。
- 原因二：新规划预创建的空行程被 Worker 误判为“修改已有行程”，因此跳过候选地点检索。
- 原因三：DashScope 可能重复选择 POI 或改写候选标题，导致草稿校验失败。
- 原因四：任务重试复用旧 LangGraph checkpoint，可能继承失败状态。
- 原因五：进度回调闭包被放入 LangGraph 状态，PostgreSQL checkpointer 无法序列化，底层错误为 `Type is not msgpack serializable: WorkflowState`。
- 修复：恢复 Elasticsearch；仅在存在 `base_snapshot` 时按修改行程处理；校验重复和白名单外 POI，并按已验证 POI ID 归一标题；每次 attempt 使用独立 checkpoint ID；通过 `ContextVar` 传递进度回调，不将函数写入 checkpoint。
- 验证：真实长沙任务成功进入 `awaiting_confirmation`，生成三天行程，地点数为 `[3, 3, 2]`，包含 8 条实时来源引用；相关测试 `51 passed`。

## 2026-08-11：消费者端 WebSocket 连接被拒绝

- 现象：浏览器提示 `WebSocket connection to ws://127.0.0.1:5173 failed: ERR_CONNECTION_REFUSED`。
- 原因：Vite 只监听 IPv6 回环地址 `::1:5173`，浏览器使用 IPv4 地址 `127.0.0.1:5173`。
- 修复：消费者端改用 `http://localhost:5173` 访问。
- 验证：`http://localhost:5173` 返回 `200`，页面和 Vite HMR 可连接。

## 2026-08-11：表单正则和社区弹窗类型警告

- 现象：浏览器提示 `Invalid regular expression`，Vue 同时提示 `ElDialog modelValue` 期望 Boolean、实际收到 Object。
- 原因：HTML `pattern` 中的连字符未按新版 `/v` 正则规则转义；社区弹窗将帖子对象直接绑定给了只接受布尔值的 `v-model`。
- 修复：将连字符写为 `\-`；使用布尔 `computed` 控制弹窗，并在关闭时清空所选帖子。
- 验证：消费者端 TypeScript 检查和生产构建通过。

## 2026-08-11：经典必玩混入旅舍和政府机构

- 现象：三亚“经典必玩”预览出现青年旅舍、旅行社、政府机关和普通餐饮等非游览地点。
- 原因：实时 MCP 搜索确实执行了，但系统将泛化网页标题直接用作高德 POI 搜索词，只校验同城，未按 POI 类别筛选景点。
- 修复：经典必玩查询补充“旅游景点、必去”意图；实时候选只接受风景名胜、公园、博物馆、展馆和海滨海岛等游览类别，并以同城景点搜索补足候选。
- 验证：三亚质量检查返回三亚湾、天涯海角、椰梦长廊、蜈支洲岛、大东海和亚龙湾等景点，未包含旅舍、旅行社或政府机构。

## 2026-08-11：景点推荐缺少审核与排序资产

- 现象：实时规划每次依赖网页标题和地图搜索，无法稳定按“经典必玩”给出已审核的热门景点。
- 原因：项目此前没有持久化的景点候选、标签、审核状态或内部热度指标。
- 修复：新增用户确认后沉淀的待审核景点池、管理员标签/权重审核、确认采用/发现次数和城市内排序；规划优先读取已批准候选，资料不足时才实时检索。
- 验证：候选审核、Worker 发现和批准候选优先工作流回归通过；迁移版本为 `20260811_0036`。

## 2026-08-11：实时景点被错误标记为地点不足

- 现象：三亚实时规划已找到 POI，但页面提示“未找到足够可验证的地点”。
- 原因：最终行程审核没有按 POI 绑定其真实候选引用，误报 `MISSING_RETRIEVAL_EVIDENCE`；前端将所有 `no_result` 统一翻译成地点不足。
- 修复：审核按已验证候选的 `poi_id -> citation.chunk_id` 精确绑定证据；来源或路线校验失败显示独立提示。
- 验证：批准候选和实时候选工作流可通过来源校验，且不再误显示地点不足。

## 2026-08-11：对话助手要求用户输入行政区划码

- 现象：消费者端旅行助手要求输入城市行政区划码，且主对话不会自动带入用户选择的行程。
- 原因：对话 API 将城市代码设为必填，并将其作为唯一公开知识检索范围。
- 修复：对话改为查询统一的官方旅行知识库，用户只输入自然语言问题；行程规划和 POI 核验仍在后端使用内部城市范围。
- 验证：无城市过滤的官方知识检索回归通过，消费者端不再显示行政区划码输入。

## 2026-08-11：对话助手一次性回答且无法补充实时资料

- 现象：助手需等待完整模型响应，官方知识库没有资料时只能返回澄清信息。
- 原因：对话链路只有同步 JSON 接口，且没有受控 WebSearch MCP 回退。
- 修复：增加持久化 assistant run、authenticated SSE `progress/delta/completed/failed` 事件和按 run ID 的终态回放；官方 RAG 仅在 `no_results` 或 `clarification_required` 时调用已配置的 MCP WebSearch。联网结果只作为当前回答的 HTTPS 元数据证据，不抓取页面、不自动入库。
- 验证：后端 assistant、PostgreSQL、router 聚焦回归 14 项通过；消费者端 typecheck 与 production build 通过。

## 2026-08-11：网络搜索摘要不足以列举具体景点

- 现象：搜索摘要仅写“十大必玩景点”等泛化标题，助手无法列出具体景点名称。
- 原因：WebSearch MCP 只提供搜索结果元数据，未读取对应页面的具体正文。
- 修复：网络回退时对最多三个 HTTPS 搜索结果调用独立 fetch MCP，将限长正文仅作为当前回答的临时来源；抓取失败时保留搜索摘要，且任何联网内容均不自动写入知识库。

## 2026-08-11：助手流式链路没有返回回答

- 现象：部分问题已经完成检索，但用户侧没有收到助手文本。
- 原因：官方 RAG 命中时流式路由错误进入异常分支，跳过了模型回答；模型临时不可用时也没有来源文本降级。
- 修复：官方命中直接进入回答生成；WebSearch 与 fetch 仅用于无结果、低置信或无关命中。模型流失败但已有来源时，持久化并推送来源摘要回答，避免空回复。

## 2026-08-11：联网来源包含 robots 拒绝文本且未按质量排序

- 现象：助手将百科、资讯页的 robots 拒绝说明、政府首页和重复搜索摘要直接展示给用户，无法形成具体景点回答。
- 原因：live_web 缺少候选重排、抓取成功验证、正文切片和去重，搜索摘要与抓取失败文本被混合送入模型。
- 修复：WebSearch 使用用户原问题，按查询覆盖、景点线索和来源质量排序去重；仅对高排名 HTTPS 结果 fetch，丢弃 robots 拒绝/不可读正文，对可读正文切片去重后才送入模型。首轮没有具体景点证据时再触发一次精确补搜。

## 2026-08-14：支付宝沙箱二维码创建和支付查询异常

- 现象一：创建会员二维码时接口返回 `503`，支付宝沙箱返回 `40002 / isv.invalid-signature`。
- 原因一：请求签名和异步回调验签共用了排除字段；请求 RSA2 签名错误排除了必须参与签名的 `sign_type=RSA2`。
- 修复一：请求签名只排除 `sign`；异步回调验签继续排除 `sign` 和 `sign_type`；测试直接用应用公钥验证实际请求签名串。
- 现象二：二维码生成后页面反复提示 `Alipay payment query is temporarily unavailable`，支付宝实际返回 `40004 / ACQ.TRADE_NOT_EXIST`。
- 原因二：支付宝沙箱响应头声明 `charset=GBK`，并使用 GBK 响应对象字节计算签名；适配器解析后固定重新编码为 UTF-8 验签，导致包含中文的业务响应被误判为验签失败。
- 修复二：网关响应按 HTTP 声明字符集严格解码，并携带同一字符集重建响应原文字节进行 RSA2 验签；成功和失败业务响应都保持严格验签；`ACQ.TRADE_NOT_EXIST` 保持为等待支付状态，不再转换成服务不可用。
- 环境边界：沙箱预下单二维码必须使用支付宝沙箱客户端和当前沙箱应用配套的买家账号测试；正式支付宝客户端扫描沙箱二维码可能显示“订单不存在”。
- 验证：真实沙箱 `alipay.trade.precreate` 返回 `10000` 和二维码；新建未支付订单的 `alipay.trade.query` 返回可验签的 `40004 / ACQ.TRADE_NOT_EXIST`；支付适配器和会员购买专项回归通过。

## 维护规则

- 优先记录最终根因，不堆积未验证猜测。
- 一次故障包含多个根因时，按“原因一、原因二”简要列出。
- 验证至少包含一个可复现结果，例如测试通过、健康检查成功或任务到达正确终态。
- 同类问题复发时更新原记录，并补充复发日期和新增原因。
